# 猜剪影 · 动漫社活动版方案

## 1. 项目定位

一个**离线桌面小工具**，用于动漫社活动现场投影互动。

核心玩法：

> 双击启动 → 主页面点【开始】→ 随机显示黑色剪影 → 观众猜 → 主持人按空格揭晓原图和角色名 → 再按空格出下一个黑影 → 一轮内不重复，全部展示完提示回主页面。

特点：

- 完全离线
- 本地抠图：优先本地 AI 模型（离线推理），模型缺失时自动降级为传统算法
- 不需要联网、房间、手机、数据库
- 最终打包成 `.exe`，双击一键启动
- 适合投影，主持人键盘操作

---

## 2. 最终交付形态

交付一个文件夹，结构如下：

```text
猜剪影/
├── 猜剪影.exe        ← 双击启动
├── 图片/             ← 把角色图拖进这里
│   ├── 漩涡鸣人.png
│   ├── 路飞.jpg
│   └── 初音未来.png
└── 缓存/             ← 软件自动生成，不用管
```

使用方式：

1. 把整个文件夹复制到活动电脑。
2. 把角色图拖进 `图片` 文件夹，文件名就是角色名。
3. 双击 `猜剪影.exe`。
4. 软件自动读取图片、生成剪影；在主页面点【开始】进入游戏（也可以直接在主页面点【添加图片】加图）。

## 3. 核心流程

### 3.1 猜谜阶段

- 纯白背景
- 角色显示为黑色剪影
- 下方答案显示“？？？”

### 3.2 揭晓阶段

- 纯黑背景
- 显示角色原图
- 下方显示角色名，也就是文件名

### 3.3 操作方式

主页面：

- 【开始】：进入游戏
- 【添加图片】：从电脑里多选图片，自动复制进 `图片` 文件夹
- 空格 / 回车：等同于【开始】

游戏中：

- 空格：揭晓答案（黑底原图 + 角色名），再按空格出下一个黑影，一直循环
- 右方向键：直接跳到下一个黑影
- Esc 或【结束本轮】按钮：结束本轮回主页面
- F11：全屏开关
- 鼠标点击按钮也可以

展示规则：一轮内图片不重复；全部展示完后显示“本轮已全部展示完毕”，按空格 / Esc / 按钮回主页面。

## 6. 图片准备规范

为了让软件自动处理效果好：

1. **文件名就是角色名**
   - `漩涡鸣人.png` → 答案就是“漩涡鸣人”
   - 不要用 `1.png`、`2.png`

2. **优先透明背景 PNG**
   - 效果最好，零处理。

3. **单人立绘最合适**
   - 只有一个角色，位置居中，背景简单。

4. **纯色或简单渐变背景也可以**
   - 软件会自动去背景。

5. **复杂背景**
   - 自动效果会差一些。
   - 可以用软件里的简单手动修正。
   - 或者提前用其他工具抠好，再放进 `图片` 文件夹。

6. **支持格式**
   - PNG、JPG、JPEG、WEBP、BMP

7. **分辨率别太低**
   - 建议短边 ≥ 600px；缩略图级别的图（如 350px 左右）抠图质量会明显下降，建议换更清晰的素材。

8. **避免"脸部特写"和"角色占满整幅画面"的图**
   - 剪影玩法需要角色有可辨认的轮廓（半身/全身），观众才能猜。
   - 脸部特写、角色撑满画面的图，剪影会是一整块，没有轮廓特征；软件会标记"建议修正"，建议直接换图。

## 7. 本地抠图方案

完全本地，不联网、不上传。优先使用内置 AI 模型（离线运行），模型缺失时自动降级为传统算法。

### 7.1 按背景分档处理

#### 第 0 档：AI 智能抠图（isnet，推荐）

- 程序目录存在 `models/isnetis.onnx` 时优先使用，对动漫立绘/截图效果最好。
- 完全离线、本地推理，一张约 1~2 秒；只在添加/处理图片时运行一次，游戏现场不受影响。
- 处理结果不合理（覆盖率异常等）时自动降级到下面的传统分档，全流程不受影响。
- 不想用 AI：config.json 里设 `"ai_matting": false`；模型获取方式见 16.4。

#### 第 1 档：透明背景 PNG

- 直接读 alpha 通道。
- 角色区域保留，背景透明。
- 然后合成白底黑影、黑底原图。
- 效果最好，推荐优先使用。

#### 第 2 档：纯色背景

- 白底、纯蓝、纯灰、纯绿最常见。
- 取四角或边缘颜色估算背景色。
- 用 Lab 色彩空间算颜色距离。
- 从图像边缘做漫水填充，只去连通到边缘的背景区域。
- 保留中间主体。
- 效果干净，几乎不用修。

#### 第 3 档：渐变背景

- 立绘常见上浅下深、中心亮四周暗的渐变。
- 从边缘采样，拟合背景色渐变模型。
- 每个像素和对应位置的背景估计值比较。
- 差异大的归为角色。
- 可用“容差滑块”手动微调。

#### 第 4 档：带纹理或简单场景的背景

- 比如樱花、光斑、简单背景元素。
- 用 GrabCut 框选主体，再自动分割。
- 效率优化：GrabCut 在大图上很慢，实际是在缩小后的图上分割、再把蒙版放大回原尺寸。
- 主体内部被包围的大空洞（例如头发轮廓里的脸）会自动填实，剪影更实心、更好猜。
- 前两档如果效果明显不行（贴边严重、背景几乎没去掉），也会自动换 GrabCut 兜底重试。
- 复杂背景自动效果会差一些，配合简单手动修正：擦除、恢复、撤销。
- 修几张就能过。

### 7.2 立绘优化点

- 主体居中假设：默认角色在画面中间，边缘大概率是背景。
- 最大连通区域：角色通常是最大的连通块，去掉小噪点。
- 边缘羽化 1～2 像素：剪影边缘不会太硬。
- 深色角色保护：揭晓时黑底可能吞掉深色角色，可加细白描边或改用深灰底。
- 统一画布比例：所有剪影缩放居中到同一画布，投影切换时不会跳动。
- 统一角色高度：按角色高度归一化，避免有的太大有的太小。

### 7.3 手动修正

不用做 Photoshop，只要够用（修正窗口全屏打开）：

- 快速选择：点一下背景残留整片去掉、点一下被误删的角色整片找回（颜色分布模型自动扩展边界，PS 快速选择同款思路）
- 画笔擦除背景 / 画笔恢复角色（带笔刷大小光标预览圈，左键=当前工具，右键=临时反向）
- 矩形框选主体（重新跑 GrabCut）
- 视图缩放：滚轮缩放（以鼠标位置为锚）、中键拖动平移、"适应窗口"按钮 / Ctrl+0 复位，放大后逐像素显示便于精修
- 笔刷大小调节
- 撤销 / 重做
- 容差滑块
- 边缘羽化滑块
- 保存并跳到下一张

现场不用修，全部活动前搞定。

## 9. 技术栈

### 9.1 编程语言

- **Python 3.10+**
  - 主开发语言
  - 生态成熟，图像处理和打包都方便

### 9.2 图形界面

- **Tkinter**
  - Python 自带，轻量，打包体积小
  - 适合这种简单界面：图片展示、按钮、快捷键
- 备选：**PySide6 / PyQt**
  - 界面更现代，但打包体积大一些
  - 如果以后想做得更精致，可以换

### 9.3 图像处理

- **OpenCV**
  - 抠图核心：颜色分析、漫水填充、GrabCut、形态学、连通域
  - 本地运行（AI 档为本地 ONNX 离线推理，不上传图片）
- **Pillow**
  - 图片读取、缩放、合成、缓存
  - 生成白底黑影图、黑底原图
- **NumPy**
  - 像素矩阵运算
  - OpenCV 和 Pillow 之间的数据转换

### 9.4 本地缓存与数据

- **文件缓存**
  - 处理后的剪影图、原图、蒙版存到 `缓存/` 文件夹
  - 格式：PNG
- **JSON**
  - 存配置和图片处理状态
  - 比如：哪些图已处理、哪些需修正、随机顺序
- **SQLite（可选）**
  - 如果以后要记录活动数据、得分、答题记录
  - 第一版不需要

### 9.5 打包与部署

- **PyInstaller**
  - 打包成单个 `.exe`
  - 目标电脑不需要装 Python
  - 完全离线运行
- 备选：**Nuitka**
  - 打包后启动更快，但配置复杂一些

### 9.6 开发与辅助工具

- **Git**
  - 版本管理
- **VS Code / PyCharm**
  - 开发 IDE
- **pytest（可选）**
  - 单元测试，主要测抠图和缓存逻辑
- **logging**
  - 记录运行日志，方便排查现场问题

### 9.7 运行环境

- **Windows 10 / 11**
  - 活动电脑通常是 Windows
- **无需联网**
- **无需安装 Python**
- **无需数据库**
- **无需服务器**

## 10. 打包与部署

开发完成后，用 PyInstaller 打包。

示例命令：

```bash
pyinstaller -F -w -n 猜剪影 guess.py
```

说明：

- `-F`：打包成单个 exe
- `-w`：不显示黑色命令行窗口
- `-n`：指定 exe 名字

打包后，`dist` 文件夹里就是 `猜剪影.exe`。

注意事项：

- 单文件 exe 首次启动会慢几秒，因为要解压依赖。
- 如果嫌慢，可以打包成文件夹模式，双击里面的 exe 启动更快。
- 不需要目标电脑安装 Python。
- 不需要联网。
- 复制整个文件夹到任何 Windows 电脑都能用。

## 16. 开发与运行（交付说明）

活动现场使用看第 1～12 节即可；本节面向开发与维护。

### 16.1 环境

- Python 3.10+（开发机实测 3.13）
- 安装依赖：

```bash
pip install -r requirements.txt
```

### 16.2 运行（双模式入口）

```bash
python guess.py                              # 打开界面（等价于双击 exe）
python guess.py --cli                        # 命令行批处理 + 质检报告，不开界面
python guess.py --cli --folder "D:\我的图"    # 指定图片文件夹
python guess.py --cli --force                # 强制重新生成全部缓存
```

`--cli` 会输出每张图的档位（透明 / 纯色 / 渐变 / 复杂）和"建议修正"清单，适合活动前批量检查。

### 16.3 测试

```bash
python -m pytest tests -q
```

覆盖：分档抠图质量（合成图对拍真实蒙版）、缓存增量与损坏自愈、坏图跳过、随机抽题（不重复 / 展示完即止）、图片入库（重名、重复内容）、配置读写、界面冒烟（主页面 → 添加图片 → 开始 → 空格循环 → 完毕页 → 手动修正）。

### 16.4 打包 exe

```bash
build.bat        # 单文件：dist\猜剪影.exe（首次启动稍慢，会解压依赖）
build.bat dir    # 文件夹模式：dist\猜剪影\（启动更快，推荐活动现场用）
```

AI 模型说明：

- 模型文件 `models/isnetis.onnx`（约 176MB）不在仓库里，从 HuggingFace 镜像获取：
  `https://hf-mirror.com/skytnt/anime-seg/resolve/main/isnetis.onnx`
  下载后放进仓库 `models/` 目录（或直接放到 exe 旁的 `models/` 目录）。
- 打包脚本会自动把模型复制到 dist 输出目录；模型不存在时生成不含 AI 的版本（传统四档照常工作）。
- 单文件模式下模型同样放 exe 旁边的 `models/` 子目录（不打进 exe，避免启动解压变慢）。

### 16.5 缓存与日志

- 图片文件夹：默认程序目录下 `图片\`，文件名（去掉扩展名）就是答案。
- 缓存目录：`缓存\<图片文件夹名>\`，内含 `state.json`（每张图的档位、质量标记、是否已人工确认）和 猜谜图 / 揭晓图 / 蒙版 三种 PNG。
- 增量机制：换图、改图、缓存损坏都会自动重新生成；抠图算法升级后旧缓存会自动整体重算；删掉 `缓存\` 可全量重来。
- 运行日志：`缓存\运行日志.log`，现场出问题先看这里。

### 16.6 配置 config.json

首次运行自动生成在程序目录，按需修改（改完重启生效）：

| 字段 | 默认 | 说明 |
|---|---|---|
| tolerance | 20 | 抠图容差（Lab 色距），越大去背景越狠 |
| feather_px | 1.5 | 边缘羽化像素 |
| reveal_mode | black | 揭晓背景：black / darkgray / original（原图背景） |
| dark_protect | true | 深色角色揭晓时自动加细浅色描边 |
| canvas_w / canvas_h | 1920 / 1080 | 统一画布尺寸（对齐投影分辨率） |
| subject_ratio | 0.82 | 角色占画布高度比例（统一大小） |
| guess_bg / silhouette_color | #FFFFFF / #000000 | 猜谜图背景与剪影颜色 |
| ai_matting | true | AI 抠图优先（需 models/isnetis.onnx；缺失时自动降级） |
